# AutoSubtitle 優化方向（2026-10-21）

目標：把字幕工房做成「一般人下載就能用」的軟體，介面全面優化，技術不限定 Python。

來源：五個面向的獨立審查（介面體驗、字幕編輯器、下載安裝、技術選型、辨識引擎），每個面向都附檔案行號或截圖證據，再由另外五位查核者逐條驗證技術主張。四份查核完成，共 155 條主張，150 條屬實；「下載安裝」那份的費用數字沒有完成二次查核，下面有標註。

**進度（2026-10-29）**：里程碑 1、2、3 完成，1.1.0 已發佈。剩下里程碑 4（換殼與引擎）與標 ◆ 的項目，要等你決定。

| 里程碑 | 狀態 | 備註 |
|---|---|---|
| 1 止血 | 完成 | 1.0.0 |
| 2 編輯器可用 | 完成 | 1.1.0 |
| 3 體驗整合 | 完成 | G4 的 A/B：同一段 20 分鐘音訊、medium、RTX 3080 Ti，逐段 78 秒、批次 19 秒，文字 95.7% 相同，所以只在 GPU 預設批次。F09 的做法和原計畫不同：沒有改成錯誤碼，而是在前端用字典即時替換畫面文字（含後端訊息），見 `ui/i18n.js` |

## 0. 結論

**現況**：介面基底不差。設計 token、深淺色、單一視窗、轉檔頁的進度與取消都已完整。但離「下載就用」差三件事：

1. **信任鏈**：沒有簽章、沒有安裝程式、沒有更新。README 和發佈說明在教使用者繞過 SmartScreen 與 Gatekeeper，這是非技術使用者最常放棄的點。
2. **第一次使用**：模型下載是黑洞。查核後比審查寫的更糟，faster-whisper 把下載進度條整個關掉，所以狀態列只會停在「載入模型中…」，幾百 MB 到 3 GB 的下載期間什麼都看不到，也不能取消。
3. **編輯器成熟度**：沒有復原、時間軸不能縮放、上千句會卡、沒有字幕品質檢查，幾個邏輯 bug 會丟掉使用者剛打的字。

**技術選型結論**：介面保留現在的 HTML/CSS/JS。它是最大的資產，和 pywebview 只有三個耦合點（取得 API 的方式、video 的來源網址、字型預覽網址）。真正修不掉的兩個天花板是 Mac 只能用 CPU、Windows GPU 版 1.1 GB，根源都在 CTranslate2，留在 Python 永遠解不掉。建議路線：

| 階段 | 做什麼 | 得到什麼 |
|---|---|---|
| 0（1–2 週，仍是 Python） | 簽章、安裝程式、更新檢查、模型管理頁、引擎的幾個零成本修正 | 現在的程式變成能安心下載的產品 |
| 1（2–3 週） | Tauri 2 當外殼，現有 Python 引擎打包成 sidecar | 正規安裝程式、自動更新、公證，一條 `tauri build` 搞定 |
| 2（6–10 週） | 引擎換成 whisper.cpp（whisper-rs） | Mac 用 Metal GPU、Windows 出 Vulkan 版通吃 NVIDIA／AMD／Intel、安裝檔 50–110 MB |
| 3（1–2 週） | 移除 Python 與 PyInstaller | 單一 Rust 執行檔，防毒誤判與啟動時間都改善 |

**需要你決定的三件事**：

- ◆ **要不要走 Tauri**。這台電腦目前只有 .NET 9，沒有 Node 與 Rust，要裝工具鏈並寫 Rust。不走的話，階段 0 的所有項目仍然值得做。
- ◆ **簽章預算**。Apple Developer 每年 US$99 是公開定價。Windows 方面審查提到 SignPath 對開源專案免費、Azure 簽章服務約每月 US$10，這兩個數字沒有完成二次查核，動手前要再確認。
- ◆ **要不要內附 ffmpeg**。內附才能開箱燒錄成品影片。查核確認現在 app.js 推薦的 gyan.dev 建置是 GPLv3 含 libx264，內附必須改用 LGPL 建置並附授權文字。PyAV 的 wheel 目前沒有 libass，程式內燒錄要等 PyAV 下一版（libass 在 2026-10-19 才進主線）。

## 附錄：查核時被修正的說法

- 模型下載進度：faster-whisper 直接把 tqdm 關掉，不是「寫到 stderr 被截斷」。必須自己下載。
- 拖放：拖入檔案的完整路徑只能從 Python 端的 DOM 事件取得。
- localStorage 失效原因是 pywebview 的 private_mode，不是 file:// 協定。
- 150% 縮放下視窗變窄的說法對 pywebview 6.2 以上不成立，釘版本即可。
- 編輯器重用轉檔頁的 TranscribeJob 需要小幅重構，不能原封不動。
- 審查給的各模型記憶體用量公式不可靠，以 faster-whisper README 的實測為準。
- 兩個入口同時辨識不會讓記憶體翻倍（CTranslate2 會排隊），但缺佇列的問題仍在。
- 批次推論與幻覺參數互斥，要取捨。
- PyAV 目前沒有 libass，程式內燒錄要等新版；gyan.dev 的 ffmpeg 是 GPLv3。
- 「下載安裝」審查的費用數字（SignPath 免費、Azure 每月約 US$10）未完成二次查核。
